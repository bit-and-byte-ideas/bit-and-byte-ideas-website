# WP-07: Metadata, structured data, sitemap, and RSS

## Purpose and scope

Make the new pages discoverable and correctly described: canonical and social meta,
JSON-LD, a content-driven sitemap with real `lastmod`, an RSS feed, and `llms.txt`
guidance. Drafts and fixtures never leak into any of them in production.

## Acceptance criteria

- **AC-1** `pageMeta()` snapshots for existing routes are unchanged.
- **AC-2** Fixture build: each project and article page has a unique title,
  description, canonical (`https://www.bitandbyteideas.com/...`, no trailing slash),
  `og:*`, `twitter:*`, an `og:image` that exists in `build/client`, and JSON-LD that
  parses and has the required properties (unit-tested builders; e2e parses the
  rendered script tags).
- **AC-3** Production build: `sitemap.xml` lists exactly `/`, `/about`, `/connect`
  (same `priority`/`changefreq` as before) plus any published entries. It is
  well-formed (parsed in e2e with `DOMParser`). Old-vs-new output diff recorded in
  evidence.
- **AC-4** `rss.xml` is well-formed, has absolute links, and has items only for included
  articles. With no published articles it is a valid empty channel and is not linked
  from any page.
- **AC-5** In a production build, no draft or fixture URL, slug, or title appears in
  `sitemap.xml`, `rss.xml`, any HTML, or any `.data` file (verify script).
- **AC-6** No structured data claims ratings, reviews, prices, or metrics.
- **AC-7** `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:e2e`,
  and `pnpm test:e2e:built` pass.
